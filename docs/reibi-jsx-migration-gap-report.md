## 這份文件是什麼

回答一個問題：**`reibi/` 資料夾內四個 JSX Artifact 的功能，哪些還沒搬到 `sleepm_merge`？**

盤點方式分三層，逐層加深：

1. **畫面與選單層**：列出四個 Artifact 的所有 `function XxxScreen` 與選單入口（主平台 53 個、L5 19 個），逐一在新系統搜尋對應實作。
2. **欄位與公式層**：比對計價、分潤、量表計分、積分、狀態機的**常數與公式**，逐一核對數值。
3. **資料鍵層**：以程式掃描四個 Artifact 的 `stor.g`／`stor.s`，取得 70 個 storage key，逐一追查新系統的對應資料表。

> **重要**：先前的 `reibi-feature-migration-checklist.md` 漏列了三項功能（不是標為待辦，是從未被盤點）。本次盤點已補進該清單。這份報告是獨立於清單、直接對照原始碼的結果。

## A. 完全沒有移植（4 項，全部需要你提供內容或決策）

| # | 功能 | Artifact 位置 | 卡在什麼 |
|---|---|---|---|
| A1 | **體驗場域** `VenueScreen` | 主平台 | 需要各體驗中心的名稱、地址、所在區域、交通方式、開放時間 |
| A2 | **方案與定價** `PricingScreen` | 主平台 3420 行 | 需要確認四層定價數字是否仍有效 |
| A3 | **關於 REIBI** `AboutREIBIScreen` | 主平台 3811 行 | 需要五個分頁的文案 |
| A4 | **訂閱閘門** `SubscribeScreen` | 主平台 | 需要商業模式決策：實作，或標記為 `[N/A]` |

### A1 體驗場域

Artifact 內含台北／新北兩個體驗中心，各有名稱、地址、所在區域、多條交通路線，以及「首次免費體驗（每人限一次）」的預約入口。全部為寫死內容。

新系統中 `體驗中心`、`體驗場域`、`首次免費` 等字串**在整個 repo 只出現於文件**，程式碼零實作。

### A2／A3 定價與關於 REIBI

兩頁都**沒有任何程式邏輯**，純粹是商業內容：

- `PricingScreen`：Layer A 軟體年授權（依人數規模）、Layer B 硬體（雲朵床 NT$80 萬／台、樂活椅 NT$75 萬／台、LA200 NT$14.94 萬）、Layer C 高管量測、Layer D 環境佈置，以及三年總建置費對照表。
- `AboutREIBIScreen`：使命與定位、理論框架、利害關係人（董事會／HR／員工各自的利益清單）、SDG 3／8／10／17 對標、888 計畫，共五個分頁。

Artifact 發布於 2026-07-30。照抄過來等於在新系統公布一份可能已過期的價目表，**比沒有這一頁更糟**。

### A4 訂閱閘門 ⚠️ 影響營收

Artifact 對「免費個人用戶」有一整套功能限制：

| 限制 | Artifact 位置 |
|---|---|
| AI 個人報告僅訂閱版可用 | 937、941 行 |
| 年度改善追蹤報告僅訂閱版可用 | 953–954 行 |
| 免費版歷史趨勢只顯示最近 3 個月 | 980、990 行 |
| 到期前 30 天提醒、到期自動降級（資料保留） | 1095 行 |

新系統前端搜尋 `isPro`、`isFreeIndividual`、「訂閱版」、「升級訂閱」—— **零結果**。

L5 側的訂閱管理（審核、一次性啟用碼、到期）已完成，但**個人用戶端完全沒有閘門**，免費用戶目前拿得到全部功能。

## B. 部分移植，欄位有缺（可立即補，不需你提供資訊）

| # | 缺什麼 | 位置 | 影響 |
|---|---|---|---|
| B1 | 工單 `globalNote`（整體備註） | `reibi_work_orders` | 無欄位可存 |
| B2 | 工單 `specialTerms`（特殊條款） | `reibi_work_orders` | 無欄位可存 |
| B3 | 工單 `dSites`（施工場域）的操作介面 | `/reibi/workflow` | 資料已從報價快照帶入 `items.dSites`，但**表單無介面可檢視或修改** |
| B4 | 報價 `bCustomNote`、`dNote`、`note` | `reibi_quotes` | 備註類欄位無處可存 |
| B5 | 報價 `cFeeBase` / `cHighRiskFee` 拆分 | `reibi_quotes` | 只存合併後的 `c_layer_fee`，看不到「方案費 + 高風險加購」的組成 |
| B6 | L5 擴展里程碑時間軸 | `/reibi/l5/regions` | 已標記 `[~]` 延後 —— Artifact 內六筆為寫死行銷內容且最後一筆（2026 Q2）已過期 |

這些都是備註與明細欄位，**不影響任何計算結果**。

## C. 刻意不移植（均有決策記錄）

| 項目 | 理由 | 副作用 |
|---|---|---|
| **B 層設備底價**（床 520,000／椅 487,500／LA200 97,110） | 不在程式碼中暴露內部底價 | **沒有「折扣後低於底價」的防呆** |
| **共用 PIN 與備援碼**（`pin_`、`rc_`、`l5_pin_*`、`l5_pin_partner_`） | 改用 Supabase Auth 邀請與 TOTP | 無 |
| **舊 `window.storage` 業務資料** | 2026-08-14 範圍決策，新資料庫乾淨起始 | `reibi_artifact_import_*` 維持 0 筆是預期狀態 |
| **C 層 `execs`（含幾位高管）／`days`（服務天數）** | 在 Artifact 僅為下拉選單的說明文字 | 報價單少了說明文字 |
| **Artifact 跨檔案交接機制**（`__rq_handoff_index_*`） | 改用資料庫外鍵（`reibi_work_orders.contract_id`） | 無 —— 這是升級而非缺口 |
| **佣金 A 層基數 fallback** | Artifact 在 `aLayerFee` 為空時退回方案定價、再退回 240,000；新系統一律使用實際簽約金額 | 以實際金額計算分潤較正確，但屬行為差異 |

## D. 已逐項核對，完全一致

### D1 計價與分潤（數值逐一比對，零差異）

| 項目 | 內容 |
|---|---|
| A 層級距 | ≤100／≤300／≤500／≤1000 人 → 60／120／180／300 萬 |
| A 層付款折扣 | 年繳 0.95、半年繳 1.0、季繳 1.03 |
| A 層空白人數防呆 | Artifact v1.9 專門修過的「錯誤 AH」，新系統有等效處理 |
| B 層設備單價 | 床 800,000／椅 750,000／LA200 149,400 |
| C 層四方案 | 35,000／70,000／105,000／210,000；高風險高管 14,000 |
| D 層六項 | min／max 金額全部相同 |
| 佣金四等級 | 銀 8／10／5、金 14／15／8、白金 20／20／12、戰略 28／28／18 |
| REIBI 保留下限 | 預設 65%，每層分潤上限 = 100 − 保留下限 |
| D 層不分潤 | Artifact v2.12 的更正，新系統一致 |

### D2 量表計分（七個量表全數一致）

含 PSS-4 第 3／4 題反向計分、BSRS-5 附加題 ≥2 強制紅燈、NMQ 取 15 部位最大值、過勞加計風險因子（上限 4）。所有燈號門檻逐一核對相同。

### D3 積分規則

打卡 5、日記 3、三高首次 20、PHQ-4／正念 5、PSS-4 10、回饋（`dept_head` 15／其他 10）、同項目 7 天間隔。22 項行動打卡的**六個分類、標籤與數量**完全一致。

### D4 狀態機

報價、合約、工單三個狀態機的狀態集合與轉移規則一致。（「已到期」在 Artifact 是顯示標籤而非儲存狀態，非缺口。）

四個 Artifact 共 70 個 storage key。其中 15 個在 `reibi-artifact-mapping.md` 從未被提及，追查後**功能均已移植**，僅是名稱不同：
