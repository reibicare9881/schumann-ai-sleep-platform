## 這份文件是什麼

回答一個問題：**`reibi/` 資料夾內四個 JSX Artifact 的功能，哪些還沒搬到 `sleepm_merge`？**

> **重要**：先前的 `reibi-feature-migration-checklist.md` 漏列了三項功能（不是標為待辦，是從未被盤點）。本次盤點已補進該清單。這份報告是獨立於清單、直接對照原始碼的結果。

### A1 體驗場域

Artifact 內含台北／新北兩個體驗中心，各有名稱、地址、所在區域、多條交通路線，以及「首次免費體驗（每人限一次）」的預約入口。全部為寫死內容。

新系統中 `體驗中心`、`體驗場域`、`首次免費` 等字串**在整個 repo 只出現於文件**，程式碼零實作。

### A2／A3 定價與關於 REIBI

兩頁都**沒有任何程式邏輯**，純粹是商業內容：

- `PricingScreen`：Layer A 軟體年授權（依人數規模）、Layer B 硬體（雲朵床 NT$80 萬／台、樂活椅 NT$75 萬／台、LA200 NT$14.94 萬）、Layer C 高管量測、Layer D 環境佈置，以及三年總建置費對照表。
- `AboutREIBIScreen`：使命與定位、理論框架、利害關係人（董事會／HR／員工各自的利益清單）、SDG 3／8／10／17 對標、888 計畫，共五個分頁。

Artifact 發布於 2026-07-30。照抄過來等於在新系統公布一份可能已過期的價目表，**比沒有這一頁更糟**。

### A4 訂閱閘門 ✅ 已完成（2026-08-19）

Artifact 對「免費個人用戶」的四條限制已全數實作，且**全部在後端執行** —— 前端隱藏按鈕不算閘門：

| 限制 | 實作方式 |
|---|---|
| AI 個人報告僅訂閱版可用 | 擋在**生成前**：免費用戶的評估照常儲存、燈號照常計算，但完全不呼叫 Gemini。擋在顯示端等於付錢產生一份不給看的報告 |
| 年度改善追蹤報告僅訂閱版可用 | `POST /api/ai-trend/{user_id}` 回 **402**（付費牆）而非 403（你不該來這裡） |
| 免費版歷史趨勢只顯示最近 3 個月 | 後端裁切並回傳 `hidden_count`；隱藏不是刪除，不回報筆數使用者會以為紀錄消失 |
| 到期前 30 天提醒、到期自動降級（資料保留） | 到期採**延遲判定**，不背景改寫任何資料列。測試明確斷言到期後資料筆數不變 |

判定沿用 Artifact 的那一行：企業員工一律視為訂閱版（A 層授權費已涵蓋），只有 `individual` 受管轄。

**這一項原本被歸類為「需要你提供內容或決策」，其中「內容」是誤判**：`SubscribeScreen` 裡沒有任何價格 ——
Artifact 的付款是人工審核制（「請透過 LINE 或 Email 提供付款證明」），金額由客服個別議定，
程式裡從來沒有這個數字。所以它只需要一個是否要做的決定。

順帶修掉一個前端問題：`API.request` 原本把 HTTP 狀態碼吞掉，402 會被顯示成一句「產生失敗」。

### 順手修掉的一個安全問題

`POST /api/reibi/health/points/redeem` 原本把 `cost` 當成前端傳來的參數，等於**讓使用者自己標價**。
Artifact 沒有這個問題，因為它的兌換鈕只是 `alert("請聯絡客服兌換")`、根本不扣點；新系統會真的扣。
現在只收 `reward_code`，點數一律查後端目錄。

D 層六項 min/max、E 層加值四項與 CPI 上限 5%、佣金四等級 —— 全數吻合。

兩處比 Artifact 好：B 層套組總價改為由設備單價即時算出（Artifact 把 1,699,400 這類數字
寫死在頁面上，設備單價一改就對不上）；B 層底價（520,000／487,500／97,110）確認完全
不存在於程式碼中，符合 C 類的刻意排除。

**順帶更正本文件先前的不精確**：§D1 只列了銀轉金 800 萬、金轉白金 2,000 萬兩個門檻，
讀起來像漏了戰略級。實際上 `STRATEGIC_REFERENCE_THRESHOLD = 50000000` 有實作，且刻意
設計成顯示用、不驅動自動升級，程式碼裡附了理由。**是文件不精確，不是程式缺漏。**
